# Bug and user-experience test report — 30 October 2026

## Outcome

- **125 Python regression tests passed; no failures or skips.**
- **134 JavaScript tests across 25 files passed; no failures or skips.** Each file was run directly to count individual tests rather than counting test files as cases.
- **28 browser UX checks passed** against a disposable library, using the real HTTP handlers and current UI.
- Six issues found and fixed, listed below. JavaScript syntax and `git diff --check` also passed.

These results cover the current development sources. No production USB files or personal catalogue were changed. The temporary library's media hashes were checked at shutdown: `original_files_unchanged: true`. The fixture and browser tabs were stopped after testing.

## Test design

The regression pass covers catalogue identity and migration, scanner caching, metadata, imports, video sync, server security and byte ranges, saved schedules, live/replay navigation, audio gain, CRT, themes, player controls and the new audio/playlist features.

Additional failure cases target likely regressions in the recent work: missing FFmpeg/FFprobe, insufficient disk space, corrupt input, encoder failure, shutdown during conversion, source replacement during conversion, concurrent requests, deleted cache files, source-folder changes, HTML-like titles, and mouse/keyboard/touch playlist activation. Actual H.264/E-AC-3 and HEVC/AC-3 test files exercise FFmpeg rather than relying solely on mocks. Output checks verify AAC stereo, the HEVC `hvc1` tag, unchanged originals, and identical decoded video frames for the H.264 integration case.

The UX library contains a working AAC recording, a working Dolby recording, a deliberately corrupt file and a missing-file entry. Search, labels, removal marks and preferences are tested on that library. The scan endpoint is stubbed to return an idle status so background discovery cannot alter the deliberate failure fixtures; catalogue saves, audio preparation, streaming and removal-register handlers are real.

## Reproduce

From the repository root:

```sh
python3 -B -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.js
python3 -B tests/serve_ux_fixture.py
```

The fixture needs FFmpeg and FFprobe, generates short sample recordings in a temporary directory and prints its localhost URL. Open that URL, follow the matrix, and stop with Ctrl+C. Shutdown reports whether the media hashes stayed unchanged. Localhost permissions are needed for server tests and the fixture.

To reproduce the individual JavaScript count, run each file directly with `node tests/NAME.test.js`. The standard test-runner summary on this environment counts files, so it reports 25 rather than the 134 individual cases.

## Limits

Firefox was not connected to browser automation, so the interactive checks used the in-app browser. The tests verify compatible AAC output and playback state; they do not establish audible output through the user's particular Firefox build, speakers or system mixer. Native Windows/macOS builds, physical touch hardware, power loss, multi-hour playback and performance on the full personal collection were not exercised. The narrow-viewport check verifies layout, not a physical phone. Those remain useful follow-up acceptance checks rather than silently assumed passes.

## Follow-up: frozen replay and TV-frame clearance

A reported Deep Space Nine replay freeze was investigated against the actual source file, read-only. The MKV declared 713,454,583 bytes, with 84,762,624 bytes allocated. Multiple 64 KiB samples, including the 1 MB and 10 MB offsets, were entirely zero-filled. FFprobe reported invalid EBML data in the missing regions. Some later packets remained readable, so this is not simply a short file with an incorrect duration: it has gaps. The original was left unchanged. Completing or rechecking its download is required; a player retry cannot reconstruct absent content.

Changes and verification:

- Added a 12-second no-progress watchdog and an explicit Retry playback action. Normal progress, pause, hidden tabs, recording changes, backward seeks and reloads reset or suppress the warning. Retry reloads the current file and preserves replay position.
- Network write timeouts are treated as interrupted transfers, preventing a JSON error response from being appended after video bytes. A regression asserts that no second response is sent.
- Goblin windowed replay now has 28 px horizontal control insets and a 22 px bottom inset, with smaller transport gaps. Its control stack cannot wrap sideways into an off-screen column.
- The changed assets use versioned URLs after the browser preview retained older stylesheet content despite reloads.
- At 1551 × 847 logical viewport size, the screen bounds were x=333.3–1144.2, y=280.2–670.3. The Previous button began at x=361.3; the close button ended at x=1116.2; transport buttons ended at y=648.3. This verifies the intended 28 px side and 22 px bottom clearance. Control scroll width equalled client width (811 px), with no horizontal overflow.
- Paused replay stayed paused without showing a stall warning. The corrected layout was checked visually on an isolated AAC replay using the same cabinet theme and transport buttons as the report.

The regression pass after these changes passed **126 Python tests and all 26 JavaScript test files** (138 individual JavaScript cases, including the four new watchdog/retry cases). The fixture media hashes remained unchanged at shutdown.

## Follow-up: initial-scan playback validation

The scanner now stores versioned, content-linked `playback_check` results for new/changed files, and backfills old entries once on rescan. It checks empty files, actual zero-filled byte samples, retained FFprobe diagnostics, browser-sensitive codecs/containers, and up to three one-second FFmpeg decode samples under a shared 12-second budget. Timeouts and unavailable tools are unverified results rather than assertions of corruption. Unchanged files reuse results; no labels, enabled flags or assignments are rewritten by the check.

Nine new Python cases cover actual good H.264/AAC media, an MP4 whose readable header still reports 10 seconds after its packet data is zeroed, sparse/gapped data, missing tools, compatibility warnings, budget expiry, cancellation and process cleanup, cache invalidation and a legacy catalogue backfill without rehashing or reprobe. Two JavaScript cases exercise broad warnings versus failed-check filters without mutating media entries.

The reported frozen episode was checked read-only with the new validator. It returned `error` in 3.21 seconds: the initial sample decoded, the midpoint and ending samples failed, and zero-filled regions/container errors were reported. The original file's size and modification time stayed unchanged. This result is local diagnostic evidence, not a repair of the missing source data.

The updated regression run passed **135 Python tests and all 26 JavaScript test files**. The directly exercised new filter cases pass. Browser checks against a freshly scanned disposable library confirmed:

- Playback issues shows the deliberately broken recording plus the Dolby compatibility warning, excluding the checked AAC recording.
- Failed playback checks shows only the broken recording in both Library and Organise & labels.
- The editor exposes the scan diagnostics, while HTML-like titles remain literal text.
- No browser console errors were reported, and fixture originals were unchanged at shutdown.

The fixture's corrupt file is now created before its initial scan, rather than added afterward, so the visible diagnostics come from the real scanner. The scanner does not automatically remove flagged videos from schedules. Spot checks cannot certify every byte or the user's Firefox/system decoder.
